# 회사 PC 배포 (Windows + 클래식 Outlook)

README의 짧은 설치 절차를 실제로 따라 할 때 필요한 세부. 사내망 설정 항목,
자동 실행 등록, 아이콘 실행, `doctor`가 대신하지 못하는 확인 항목을 담는다.

## 1. 준비

1. **Windows 네이티브 Python 3.11+** 설치 — WSL로는 안 된다(COM 접근 필요).
   3.11 이상인 이유는 표준 라이브러리 `tomllib`를 쓰기 때문이다.
2. `pip install pywin32` — 코어에서 유일하게 필요한 외부 패키지다.
   프록시 뒤라면 `pip install --proxy http://<프록시>:<포트> pywin32`.
3. **AI 기능을 쓸 것이면 CLI 하나가 PATH에 있어야 한다.** 내장 백엔드 이름
   `sonnet`/`haiku`/`opus`는 `claude -p --model <이름>`을, `internal`은
   `opencode run`을 부른다(`config._BUILTIN_BACKENDS`). 사내 CLI를 쓴다면
   §2의 `[ai.backends.*] cmd`로 지정한다. **없어도 AI 기능만 빠지고 나머지는
   전부 동작한다** — 수집·검색·회고·웹 UI는 네트워크 호출이 0이다.
4. **저장소를 받는다.** `git`이 없는 PC라면 GitHub의 **Code › Download ZIP**으로
   받아 풀어도 된다 — 그때는 갱신도 다시 받는 방식이고, 웹의 '최신으로 업데이트'
   버튼은 git이 없다고 안내만 한다.

```
git clone https://github.com/dongjinpark-maker/mailkb
cd mailkb
python -m mailkb init
python -m mailkb doctor          # 여기서 막히는지 먼저 본다 (§5)
```

`init`은 데이터 홈을 코드 폴더 옆 `<mailkb>\data\`에 만든다(사용자 홈은 쓰지 않는다).
`data/`는 gitignore라 `git pull`이 실데이터·설정을 건드리지 않는다.

**`doctor`를 §2보다 먼저 돌리는 이유가 있다.** ① Outlook COM이 되는지를 설정
채우기 전에 알 수 있고, ② `[Outlook] MAPI 계정` 줄이 **내 메일 주소를 알려 줘서**
§2의 `my_addresses`에 그대로 넣으면 된다. 이 단계에서 `my_addresses` 실패가 뜨는
것은 정상이다(아직 안 채웠으니까) — 볼 것은 `[Outlook]` 절이다.

## 2. 사내망 설정 — `<mailkb>\data\config.toml`

**저장소와 코드 안의 값은 전부 가상 예시다.** 실환경 값은 이 파일에만 넣는다.
다른 위치에 두려면 `--home` 또는 환경변수 `MAILKB_HOME`을 쓴다.

| 항목 | 넣을 값 | 왜 중요한가 |
|---|---|---|
| `my_addresses` | 실제 회사 주소 | **메일 별칭(alias)으로도 발신한다면 별칭 주소를 함께 나열한다.** 빠뜨리면 내 발신이 수신으로 오분류된다 |
| `my_names` | 내 이름·호칭 (예: `["홍길동", "길동"]`) | 본문이 나를 지목했는지 판정한다. 그룹메일에서도 확인 대상으로 유지되므로 미답변·기한 판정의 과탐을 줄이는 핵심 |
| `internal_domains` | 사내 도메인 | 설정하면 외부 도메인 발신을 **전부** 노이즈로 제외한다. 협력사가 있으면 아래 `external_allowlist`를 반드시 함께 채운다 |
| `[filters] external_allowlist` | 추적할 협력사 도메인·주소 | `internal_domains`를 켠 상태에서 예외로 살릴 목록. 예: `["partner.co.kr", "kim@vendor.com"]`. **비워 두면 고객사·협력사 메일이 미답변·기한 판정에서 조용히 사라진다** |
| `[filters] subject_noise_strong` | **실제 사내 시스템의 제목 패턴** (전자결재·알림·설문 등) | 코드 기본값의 `[nflow]`/`[nwork]`는 가상 예시다. 이 단계를 건너뛰면 실환경 결재·알림 필터가 동작하지 않는다 |
| `[review] broadcast_to` | 조직 규모에 맞춘 값 | 기준은 **실무 그룹 메일은 포함되고 팀·전사 공지만 배제되는 값**. 예: 그룹 –80명·팀 –400명 조직이면 50 (20–30명 실무 메일은 유지, 전체 발송만 배제) |
| `[sources] include_subfolders` | 기본 `true` — 그대로 두면 된다 | 받은 편지함 **하위 폴더**까지 수집한다. **규칙으로 수신 메일을 자동 분류하고 있다면 이 값이 생명줄이다** — 꺼져 있으면 그 메일이 색인에 아예 안 들어오는데 화면에는 아무 표시가 없다. 지운 편지함·정크는 항상 제외 |
| `[sources] exclude_folders` | 뺄 폴더 (예: `["뉴스레터", "inbox/보관"]`) | 이름 또는 상대 경로, 대소문자 무시. 웹 **설정 › 수집 폴더**에서도 켜고 끌 수 있다 |
| `[sources] max_folders` | 기본 50 (0=무제한) | 동시에 여는 폴더 상한. 넘으면 얕은 폴더부터 채우고 나머지는 건너뛰되 `sync`·`doctor` 가 건너뛴 폴더를 출력한다 |
| `source` | `"outlook"` | `init`이 이미 이 값으로 만든다. 데모만 `fake` |
| `[ai.backends.*] cmd` | 실제 사내 LLM CLI 호출 형태 | 프롬프트를 stdin으로 받고 응답을 stdout으로 내는 명령이면 무엇이든 된다 |
| `[ai] diagnose` | 현안 브리핑 백엔드 (기본 `opus`) | 스레드·인물 화면의 [현안 브리핑]이 쓴다. **쓰는 CLI 가 opus 를 못 부르면 이 버튼만 실패한다** — `mailkb diagnose` 가 실제 호출로 확인해 주고, 웹 **설정 › 현안 브리핑**에서 sonnet 으로 바꿀 수 있다 |
| `ai-rules.md` (같은 폴더) | AI 에게 줄 자연어 지침 — 사내 용어 풀이·호칭·우선순위 | `init` 이 주석만 든 템플릿을 만든다. 주석 밖에 평문으로 쓰면 수확·분석·주간 보고 프롬프트에 `[사용자 지침 — 우선 적용]` 으로 실린다(검증 콜 제외). HTML 주석은 AI 가 보지 않고, 저장 즉시 반영, 상한 4,000자 |
| `[ai] ask` | 분석 전용 백엔드 | 미설정이면 `[ai] search`를 상속한다. 분석은 한 질문에 **최대 12콜**을 쓰므로, 비용이 걱정되면 검색과 분리해 지정한다. 웹 **설정 › 분석**에서도 바꿀 수 있다 |

`[ai] summary_max_days` (기본 **1** — 오늘만): 수확이 소급하는
날짜 창. 며칠 건너뛴 뒤 그 사이의 결정까지 수확하려면 2나 3으로 올린다. 늘린 만큼
AI 입력이 늘어난다.

그 외 `[review]` 항목:

- `stall_workdays` (기본 2) — 내가 넘긴 공이 안 돌아온 기준, **영업일**
- `stale_workdays` (기본 3) — 멈춘 스레드 기준, **영업일**
- `direct_to` (기본 4) — 직접 수신 판정 기준 수신자 수
- `holidays` — 대한민국 공휴일 2026(대체 포함)이 기본 내장. **음력 공휴일은 연 1회 갱신**해야 한다

설정은 웹 UI **설정** 화면에서도 바꿀 수 있다. 그쪽 변경은 `overrides.json`에
쌓이므로 `config.toml`은 손상되지 않는다.

## 3. 첫 수집

Outlook을 실행한 상태에서:

```powershell
python -m mailkb sync --since (Get-Date).AddMonths(-6).ToString("yyyy-MM-dd")
```

**첫 수집은 `--since` 로 좁히기를 권한다.** 인물 화면이 최근 6개월 교류를 창으로
쓰므로 6개월이면 모든 화면이 채워지고, 그만큼 첫 실행이 짧아진다. `--since` 없이
돌리면 사서함 전체를 백필하며 크기에 따라 수 분에서 수십 분 걸린다. 이후는 증분이다.
나중에 더 옛날 것이 필요해지면 더 이른 `--since` 로 한 번 더 돌리면 된다
(이미 있는 메일은 Message-ID 로 건너뛴다).

**받은 편지함 하위 폴더도 함께 수집한다**(기본값). 규칙으로 수신 메일을 자동
분류하고 있다면 이게 없으면 색인이 거의 빈 채로 남는다. `sync` 는 시작할 때
어떤 폴더를 훑고 무엇을 건너뛰는지 출력하고, **처음 보는 폴더는 그 한 번만
전체를 읽는다**(이미 분류돼 있던 옛 메일은 증분 기준보다 과거라 그렇지 않으면
영영 안 들어온다). 그래서 폴더가 많으면 첫 실행이 길어질 수 있다 — 무엇이
길어지는지는 `doctor` 가 미리 보여 준다.

## 4. 실행

루트 배치 파일(`mailkb.bat`/`sync.bat`)은 2026-07-11 제거했다 — 메일 전송 필터에
걸리는 문제 때문이다. 명령을 직접 쓴다.

```
python -m mailkb serve --app       # Minerva 웹 UI (Edge 앱 모드 — 창을 닫으면 서버도 종료)
python -m mailkb sync              # 증분 수집 (Outlook 실행 상태)
```

### 아이콘으로 실행 (앱처럼)

터미널 없이 바탕화면·작업표시줄 아이콘으로 연다. 저장소의 **`launch_minerva.pyw`**가
클릭 한 번에 ① 떠 있던 서버 종료 ② `serve --app` 시작(콘솔 없음 — pythonw)까지
하고, 창 열기와 **창을 닫으면 서버도 내려가는 것**은 서버가 맡는다. 재시작·종료
버튼은 없다. 다시 아이콘을 누르면 새 서버로 뜬다.

```
1. launch_minerva.pyw 우클릭 → 바로 가기 만들기 → 바탕화면/작업표시줄에 고정
2. 바로 가기 속성 → 대상을  pythonw.exe "<mailkb>\launch_minerva.pyw"  로,
   아이콘 변경 → 저장소의 minerva.ico 지정
3. (더 앱 같은 설치) 창이 뜬 뒤 Edge 메뉴 → 앱으로 설치 →
   시작 메뉴·바탕화면에 파비콘 아이콘으로 등록
```

창-서버 수명은 **페이지가 서버에 창 상태를 알려** 묶는다 — 마지막 앱 창을 닫으면
최대 6초 뒤 서버가 끝나고, 터미널에서 Ctrl-C 로 서버를 끝내면 최대 8초 안에 창이
닫힌다. 창 프로세스를 추적하는 방식은 Edge 가 창을 이미 떠 있는 인스턴스에 넘겨
성립하지 않아 걷어냈다(2026-08-09 실측 — 자세한 배경은 ARCHITECTURE §7.11).
비용은 창 하나당 서버 CPU 하루 2.2초(0.002%)로 무시할 수준이다.

**최신 코드 반영**은 매 실행마다 하지 않는다(시간 낭비). **설정 › 최신으로 업데이트**
버튼이나 터미널 `git pull` 후 **창을 닫았다 다시 열면** 적용된다.

### 자동 동기화

Windows 작업 스케줄러에 직접 등록한다(등록 스크립트는 제거했다 — 아래 한 줄로 충분).

```
schtasks /Create /TN mailkb-sync /SC HOURLY /MO 2 ^
  /TR "cmd /c cd /d <mailkb 경로> && python -m mailkb sync"
schtasks /Run    /TN mailkb-sync     # 등록 직후 시험 실행 (Outlook 켠 상태 권장)
schtasks /Query  /TN mailkb-sync     # 확인
schtasks /Delete /TN mailkb-sync /F  # 해제
```

데이터 폴더가 코드 기준 고정(`<mailkb>\data`)이라 스케줄러가 다른 작업 디렉토리에서
실행해도 안전하다(빈 DB가 생길 위험 없음).

웹 UI 자체도 열려 있는 동안 주기적으로 동기화한다(설정에서 주기 조절). 즉시
받고 싶으면 상단 **↻** 아이콘을 누른다.

## 5. 신규 환경에서 확인할 것

**`doctor` 를 먼저 돌린다.** 아래 목록의 대부분을 대신하고, 실패마다 처방을 함께
낸다. **`init` 전에도 돌아가고**, 읽기만 하며 파일을 만들지 않는다. AI 호출 0.

```
python -m mailkb doctor
```

맨 위 네 줄이 **무엇이 되고 무엇이 안 되는지**를 먼저 말한다. 항목을 다 읽지
않아도 여기서 판단이 선다.

```
  ■ 실패  메일 수집          막혀 있습니다
  ■ 실패  Outlook 원문 열기  막혀 있습니다
  ● 통과  검색·회고·웹 UI    됩니다 (이미 모은 메일로)
  ▲ 주의  AI 기능            쓸 수 있는 백엔드가 없습니다
```

예를 들어 **pywin32 가 없으면 수집과 원문 열기만 막히고** 이미 모은 메일로 하는
검색·회고·웹 UI 는 그대로 된다. 그 구분이 이 요약에서 바로 보인다.

그 아래 항목: Python 버전 · pywin32 · Outlook COM 연결(클래식인지) · MAPI 계정 ·
**프로그래밍 방식 액세스** · **수집 폴더 범위**(하위 폴더 목록과 통수, 제외 사유) ·
`my_addresses` 가 Outlook 계정과 맞는지 · **공휴일 목록이 올해를 덮는지** ·
DB 상태 · AI 실행 파일 PATH.

프로그래밍 방식 액세스 점검은 메일 한 통의 발신자 주소를 실제로 읽는다. 그게
가드가 실제로 막는 대상이라 그렇다 — **보안 경고가 뜨면 [허용]을 누르면 되고,
그 팝업이 뜬 것 자체가 결과다.** 수집이 수십 분 돈 뒤에 같은 곳에서 막히는 것보다
지금 보는 편이 낫다.

`doctor` 가 대신하지 못하는 것(사람 눈이 필요하다):

- [ ] Exchange 주소가 SMTP로 나오는지 (`mailkb ls`에서 발신자 주소 확인)
- [ ] `is_sent` 판별 정상 여부 (`→` 마크) — `my_addresses` 설정과 대조
- [ ] 증분 sync 속도 (`sync` 출력의 소요 시간)
- [ ] `mailkb open <번호>`로 Outlook 원문 열기
- [ ] AI를 쓸 계획이면 `mailkb diagnose`로 백엔드 **응답** 확인 — 역할이 쓰는
      백엔드마다 1회씩 부른다(기본 설정이면 sonnet·opus 둘). `doctor` 는 실행
      파일이 PATH 에 있는지까지만 본다. **쓰는 CLI 가 opus 를 지원하지 않으면
      여기서 드러난다** — 그때는 웹 설정 › 현안 브리핑을 sonnet 으로.
      터미널을 안 열 거면 **웹 설정 › 이 PC 에서 쓸 수 있는 AI**의 [응답 시험]이 같은 일을
      한다(모델별 응답 + opencode 유무)

### Outlook 에서 지운 메일은 어떻게 되나

색인에는 남는다. 그게 이 도구의 값이다 — 용량 정리로 지웠어도 검색·분석은 계속
된다. 다만 **원문 열기는 안 되고**, 한 번 시도해 실패하면 그 메일은
`Outlook에 없음` 으로 표시되고 **미답변·개입 판정에서 빠진다**(열리지도 않는
메일이 '회신 필요'로 남으면 목록을 못 믿게 된다). 지운 편지함에서 복구하면
다음 열기 성공이 표시를 지운다.

색인에서도 정말 지우는 기능은 아직 없다. 민감한 내용이라면 `data/` 폴더를
통째로 지우고 다시 수집하는 것이 현재의 유일한 방법이다
(설계 조사는 ARCHITECTURE §12 에 있다).

## 6. 백업

데이터 폴더(`<mailkb>\data` — `db.sqlite` + `config.toml` + `vault/`) 복사 한 번이면
된다. 연 200–300MB 수준이다.

## 7. New Outlook 리스크

회사가 `olk.exe`(New Outlook)로 강제 전환하면 COM이 사라진다. 그때는
`mailkb/sources/` 어댑터만 교체하면 된다(EWS/IMAP). 나머지 코드는 원본 접근을
어댑터 뒤에 숨겨 두었으므로 무변경이다.
